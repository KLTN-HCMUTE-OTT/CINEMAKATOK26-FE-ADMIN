## 1. Current Issues (with severity)

### CRITICAL (Security)

#### 1.1 Tokens stored in `localStorage` — XSS attack surface
**Files:** `src/libs/request.ts`, `src/libs/api/axios-instance.ts`, `src/contexts/AuthContext.tsx`

```ts
// CURRENT — exposed to any JavaScript on the page
localStorage.setItem('accessToken', response.token.accessToken)
localStorage.setItem('refreshToken', response.token.refreshToken)
localStorage.setItem('user', JSON.stringify(userData))
```

**Why critical:** Any XSS injection (e.g. from a malicious npm package, CDN script, or user-generated content) can steal both tokens. For an **admin** panel this is catastrophic — an attacker gains full control of the platform.

**Fix:** Move to `httpOnly` cookies managed by the backend (or a Next.js Route Handler acting as a BFF proxy). The middleware already reads cookies for route protection — the infrastructure is there.

---

#### 1.2 Refresh token sent in request body over bare axios call

```ts
// src/libs/request.ts line 74
const response = await axios.post(`${process.env.NEXT_PUBLIC_API_URL}/auth/refresh`, { refreshToken })
```

This bypasses the main `instance` interceptors and has no timeout, no retry backoff, no error normalisation. A race condition exists: if two concurrent 401 responses both fire, two parallel refresh calls are made.

## 4. Step-by-step Upgrade Roadmap

### Phase 1 — Foundation Cleanup (Week 1–2)

**Goal:** Eliminate critical security issues and technical debt before new features.

#### Step 1.1 — Fix token storage security (CRITICAL)

Create a Next.js BFF auth layer:

```ts
// src/app/api/auth/login/route.ts
import { NextResponse } from 'next/server'

export async function POST(request: Request) {
  const body = await request.json()
  const response = await fetch(`${process.env.API_URL}/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body)
  })

  const data = await response.json()

  const res = NextResponse.json({ user: data.user })

  // Set httpOnly cookies — inaccessible to JavaScript
  res.cookies.set('accessToken', data.token.accessToken, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
    path: '/',
    maxAge: 60 * 15 // 15 minutes
  })

  res.cookies.set('refreshToken', data.token.refreshToken, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
    path: '/api/auth/refresh', // restrict refresh token path
    maxAge: 60 * 60 * 24 * 7 // 7 days
  })

  return res
}
```

Update `AuthContext` to call `/api/auth/login` (the BFF route) instead of the backend directly. Remove all `localStorage.setItem('accessToken', ...)` calls.

Update `src/libs/request.ts`: remove `localStorage.getItem('accessToken')` — the cookie is sent automatically with `withCredentials: true`.

### Phase 2 — State Management & Data Layer (Week 3–4)

**Goal:** Predictable state, no prop drilling, consistent data fetching.

#### Step 2.1 — Add Zustand for global UI state

```bash
pnpm add zustand
```

```ts
// src/store/ui.store.ts
import { create } from 'zustand'

interface Toast {
  id: string
  message: string
  type: 'success' | 'error' | 'warning' | 'info'
}

interface UIState {
  toasts: Toast[]
  globalLoading: boolean
  addToast: (toast: Omit<Toast, 'id'>) => void
  removeToast: (id: string) => void
  setGlobalLoading: (loading: boolean) => void
}

export const useUIStore = create<UIState>(set => ({
  toasts: [],
  globalLoading: false,
  addToast: toast =>
    set(state => ({
      toasts: [...state.toasts, { ...toast, id: crypto.randomUUID() }]
    })),
  removeToast: id =>
    set(state => ({
      toasts: state.toasts.filter(t => t.id !== id)
    })),
  setGlobalLoading: globalLoading => set({ globalLoading })
}))
```

**Rule:** Only Zustand for cross-cutting UI state (toasts, modals, loading). Feature state stays local or in feature hooks. Server state belongs to SWR.

#### Step 2.2 — Standardise data fetching with SWR

Current pattern is inconsistent — some hooks use SWR (`utils/api.ts`), others use `useState + useEffect + axios` directly. Establish a single pattern:

```ts
// src/features/content/movies/hooks/useMovies.ts
import useSWR from 'swr'
import { movieService } from '@/services'

export function useMovies(params: MovieListParams) {
  const key = ['movies', params] // SWR key as array for automatic stringification
  const { data, error, isLoading, mutate } = useSWR(key, () => movieService.list(params), {
    revalidateOnFocus: false,
    errorRetryCount: 3
  })

  return {
    movies: data?.items ?? [],
    total: data?.total ?? 0,
    isLoading,
    error,
    refresh: mutate
  }
}
```

**Key rules:**
- SWR key = `[endpoint, params]` array — avoids cache collisions
- Always return typed `movies: Movie[]`, never `data: any`
- Optimistic updates via `mutate(updatedData, false)` then revalidate

#### Step 2.3 — Eliminate prop drilling with feature-level context

For complex features like `SeasonsManagement` that pass data 3+ levels deep:

```tsx
// src/features/content/tvseries/contexts/SeasonContext.tsx
const SeasonContext = createContext<SeasonContextType | null>(null)

export function SeasonProvider({ seriesId, children }: Props) {
  const { seasons, isLoading, addEpisode, removeEpisode } = useSeasons(seriesId)
  return <SeasonContext.Provider value={{ seasons, isLoading, addEpisode, removeEpisode }}>
    {children}
  </SeasonContext.Provider>
}

export const useSeason = () => {
  const ctx = useContext(SeasonContext)
  if (!ctx) throw new Error('useSeason must be inside SeasonProvider')
  return ctx
}
```

#### Step 4.4 — Add debounce to search inputs

```ts
// src/hooks/useDebounce.ts
export function useDebounce<T>(value: T, delay = 300): T {
  const [debounced, setDebounced] = useState(value)
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay)
    return () => clearTimeout(timer)
  }, [value, delay])
  return debounced
}

// Usage in search
const debouncedSearch = useDebounce(searchTerm, 400)
const { movies } = useMovies({ search: debouncedSearch, page })
```

// User ban — instant UI feedback before server confirms
async function handleBanUser(userId: string) {
  // Optimistically update cache
  mutate(
    ['users', params],
    prev => ({
      ...prev,
      items: prev.items.map(u => u.id === userId ? { ...u, status: 'banned' } : u)
    }),
    false // don't revalidate yet
  )

    await usersService.ban(userId)
    toast.success('User banned')
  } catch {
    mutate(['users', params]) // revert: revalidate from server

  }
}

## Decision Log

| # | Decision | Alternatives Considered | Rationale |
|---|----------|------------------------|-----------|
| 1 | Zustand for global UI state | Redux Toolkit, Jotai | No boilerplate, no need for DevTools time-travel in a UI store; RTK better for complex server-cache sync but that's covered by SWR |
| 2 | SWR over React Query | React Query (TanStack Query) | SWR already installed and partially used; React Query is more powerful but migration cost exceeds benefit for current scale |
| 3 | BFF Route Handlers for auth | Backend sets httpOnly cookies directly | Admin FE controls its own cookie policy without requiring backend changes; can add BFF-level validation |
| 4 | Sonner for toasts | React Hot Toast, MUI Snackbar | Smallest API surface, works with Next.js App Router, no Provider needed |
| 5 | Vitest over Jest | Jest | Native ESM support, faster, compatible with Vite ecosystem; no need for babel transform |
| 6 | Feature-slice structure | Pure Atomic Design, Domain-Driven | Scales better for large teams; each feature is independently navigable |
